Graphical interface

Looking from the top, you will see a number of tabs such as "Aircraft", "Environment", "Map", "Tools", "Simulator", providing various functions and possibilities described below.

In addition, each subpage contains the same widgets displayed on the right, such as:

  1. METAR of a nearby airport;
  2. PFD (Primary Flight Display), i.e. a display with the main flight parameters, such as position relative to the horizon, speed and altitude;
  3. radio stack with frequency settings for COM1, COM2, NAV1, NAV2, ADF;
  4. minimap from OpenStreetMap;
  5. stopwatch.

At the top on the right, you always have the following buttons available:

  1. Refresh Page - clicking this button will refresh the Phi webpage.
  2. Pause - clicking this button will pause the simulation.
  3. Play - clicking this button will unpause the simulation.

Aircraft

This tab contains information about the selected aircraft. It also allows you to view and install other aircraft available in the official hangar (FGAddon).

Help

This tab displays information about the aircraft, hotkeys, speed limits and other additional information and tips. The information contained here depends on the particular aircraft. In the simulator, this information can be obtained from the "Help" > "Aircraft Help" menu.

Mass & Balance

This tab displays information about fuel and payload of aircraft. You also have an envelope with selected center of gravity. In the simulator, this information can be obtained from the "Equipment" > "Fuel and Payload" menu.

Checklists

This tab displays all checklists provided by the selected aircraft. The information depends on the aircraft you chose. In the simulator, this information can be obtained from the "Help" > "Aircraft Checklists" menu.

Select

Here you have a list of all available aircraft in the official FGAddon hangar. The list includes such information as:

  • aircraft name;
  • thumbnail of the aircraft;
  • description (if available);
  • ratings on a scale of 1 to 5 for FDM, Systems, Cockpit and Model;
  • aircraft package size in KB;
  • ability to download and install the aircraft. If the aircraft is installed then "installed" label is displaying.

Environment

This tab allows you to change the date, time of day, check the weather and check airport data.

Date & Time

Here you can change the time of day by indicating presets, where "Clock Time" means setting the real time as it is in the location where the aircraft is. Here you can also change the date in the simulator as well as set the UTC time to the minute.

Weather

You have a weather diagram here:

  • the left vertical axis shows the atmospheric pressure in hPa;
  • the lower horizontal axis shows the temperature from -50°C to +50°C;
  • the right vertical axis represents the altitude from 0 km (sea level) to 16 km;
  • the red graph shows the air temperature in °C;
  • the green graph shows the dew point temperature in °C;
  • the gray rectangles represent the cloud layers;
  • in the right part of the graph, you also have wind arrows showing the direction and speed of the wind at particular heights.

Position

Here you can search for any airport (by ICAO code or name) and move the aircraft to the specified runway. In addition, you have here various information about the airport, such as elevation, geographical coordinates, communication frequencies, a map with the layout of runways, information about runways, the actual METAR.

Map

The main part of this view is filled with a map downloaded from OpenStreetMap as default, which shows the current position of the aircraft. The map can be freely moved, zoomed out or zoomed in. You can also add additional layers to the map, such as flight history, planned route, airports, navigation aids, other traffic and much more.

An interesting feature is also the fact that you can grab the aircraft with the mouse cursor and move it anywhere on the map. However, you can often do it accidentally, while moving the map, so using the icon in the upper right corner of the map ("Allow dragging own aircraft"), you can also disable the possibility of moving our aircraft.

Tools

This tab contains various helpful tools for the pilot.

Holding Pattern

Here you can determine how to properly fly into the holding pattern depending on the direction from which you are coming. You have to set "Inbound Track" of holding pattern, "Heading" of your aircraft and select whether holding is "left" or "right". After that, the image will show you how to properly fly into the holding pattern.

Stopwatch

Here you have a stopwatch at our disposal, and you can add many independently operating stopwatches.

Simulator

In this tab you will find options related to the simulator.

Screenshots

Here, as an instructor, you can preview what is happening in the simulator, or otherwise you have a preview of what the pilot sees. At the top, you have the option to set how often you want to receive a new screenshot from the FlightGear. If you need a smoother preview of what the pilot is doing in the simulator, you should use the "/screenshot" URL.

Properties

Here you can view and change the value of each property available in FlightGear. For a person very familiar with FlightGear, it will be a powerful tool with the ability to change any parameter or simulation state. It may be more convenient to use than the "Debug" > "Browse Internal Properties" menu option available in the simulator.

Alternatively, you can use the "/props/" URL for access another Property Browser, where the URL path can be set as full path to the property, e.g. "/props/position/altitude-ft".

Another very useful option is the function of drawing graphs of any property, which will be useful for flight analysis. It is enough to go to the given property, e.g. "/position/altitude-ft", where you have a small image icon ("toggle plot"). When you click this icon, a real-time graph will be drawn at the top of the page, showing changes in the value of the indicated property over time - in our example, the altitude relative to the sea level. In this way, you can turn on several properties and plot their values on one graph.

Config

Here you have the option of enabling artificial air traffic, as well as the possibility of connecting to the multiplayer mode.

Reset

Here you have the option to reset the simulator, the same as the option from the "File" > "Reset" menu in the simulator.

Exit

Here you have the option to exit the simulator, the same as the option from the "File" > "Quit" menu in the simulator. After closing the simulator, you will not be able to restart it with Phi.

API

GET /screenshot

Get the screen shot from the simulator window or canvas.

Parameters

  • type – image format, can be png or jpg (default). Compression level for PNG is hard coded to 9 (highest) and JPEG quality hardcoded to 80%.
  • window – as value you must provide a name of the window to capture (for those with multi screen setups).
  • canvasindex – as value you must provide the texture index of the canvas (as an integer), e.g. PFD in an aircraft with a glass cockpit.
  • stream – enable Motion JPEG stream; any character can be passed as value, e.g. 1 or y.

Examples

Single screenshot of default window in JPG format:

    GET http://localhost:8080/screenshot

Single screenshot in PNG format:

    GET http://localhost:8080/screenshot?type=png

Single PNG screenshot from the window named WindowA as defined under /rendering/camera-group/window/name in your screen configuration:

    GET http://localhost:8080/screenshot?type=png&window=WindowA

Single screenshot of specific Canvas in JPG format:

    GET http://localhost:8080/screenshot?canvasindex=6

Motion JPEG encoded video stream for specific window:

    GET http://localhost:8080/screenshot?window=WindowA&stream=1

Motion JPEG encoded video stream for specific canvas:

    GET http://localhost:8080/screenshot?canvasindex=6&stream=1

The Motion JPEG can be used by FFMPEG to directly encode various video formats:

    ffplay -f mjpeg http://localhost:8080/screenshot?stream=1

GET /json

Get properties tree in JSON format.

Examples

Get root / property tree:

    GET http://localhost:8080/json/

Get /position node with his children values:

    GET http://localhost:8080/json/position

Get /position/altitude-ft property value:

    GET http://localhost:8080/json/position/altitude-ft

POST /run.cgi

Send a command to the FlightGear to execute.

Parameters

  • value – fgcommand name.

Body

Node structure in JSON format, depends of value parameter.

Examples

Send pause command for pause/unpause the simulator (body not required):

    POST/GET http://localhost:8080/run.cgi?value=pause

Send a request to open a specific dialog by its name:

    POST http://localhost:8080/run.cgi?value=dialog-show
    BODY {
        "name": "",
        "children": [
            {
                "name": "dialog-name",
                "index": 0,
                "value": "location-in-air"
            }
        ]
    }

Send a request to change property value (switching on the battery in the Cessna 172P):

    POST http://localhost:8080/run.cgi?value=property-assign
    BODY {
        "name": "",
        "children": [
            {
                "name": "property",
                "index": 0,
                "value": "/controls/switches/master-bat"
            },
            {
                "name": "value",
                "index": 0,
                "value": "true"
            }
        ]
    }

Send a request with a Nasal script to be executed:

    POST http://localhost:8080/run.cgi?value=nasal
    BODY {
        "name": "",
        "children": [
            {
                "name": "script",
                "index": 0,
                "value": "gui.popupTip('Hello, this is Phi');"
            }
        ]
    }

GET /flighthistory/track.json

Get flight path history in JSON format. The path consists of coordinates, each coordinate has the format "lon,lat,altitude".

Parameters

  • count – number of coordinates of the recorded path. Default is -1, i.e. all coordinates.
  • last – a timestamp in milliseconds. If you provide it, older recorded path coordinates will be skipped. The default is 0, which means all coordinates will be sent.

Examples

Get all flight history coordinates:

    GET http://localhost:8080/flighthistory/track.json

As a result, you will get a response in JSON format with last timestamp to use in next request:

    {
        "type": "Feature",
        "geometry": {
            "type": "LineString",
            "coordinates": [
                [16.882262, 51.103904, 192.726014],
                [16.882864, 51.103721, 196.063745],
                [16.883477, 51.103531, 199.307147]
            ]
        },
        "properties":{
            "type": "FlightHistory",
            "last": 92141
        }
    }

Get the next flight history coordinates from a specific timestamp:

    GET http://localhost:8080/flighthistory/track.json?last=92141

GET /flighthistory/track.kml

Get flight path history in KML format. The path consists of coordinates, each coordinate has the format "lon,lat,altitude".

Parameters

  • interval – number of seconds, how often the KML file will be automatically refreshed. If you don't specify this parameter, automatic refreshing will not be started.
  • LineColor – line color, default 427ebfff.
  • LineWidth – line width, default 4.
  • PolyColor – polygon color, default fbfc4600.

Examples

Get flight history coordinates with line with 8:

    GET http://localhost:8080/flighthistory/track.kml?LineWidth=8

GET /navdb

Get information about navigation aids, airports, towns, etc.

Parameters

  • i – indent; if you want to specify it, you must use the value y, then a space character will be used between the returned items.
  • q – required query parameter. The following values can be used:
    • airports – get list of all airports with name and ICAO code.
    • airport – get information for the specific airport. The airport ICAO code must be given with id parameter.
    • findWithinRange – here you need to use the lat and lon parameters to specify the point around which you are searching, range where you specify the radius in NM from the geographic point, and type which specifies what you are looking for.
  • lat – latitude required for q=findWithinRange.
  • lon – longitude required for q=findWithinRange.
  • range – range required for q=findWithinRange. The range cannot be less than 1.0 NM.
  • type – here you can specify what navigation aids you are looking for, which is required for the q=findWithinRange parameter. You can list here, after a comma, the following values: airport, country, city, dme, fix, gs (glide slope), heliport, ils, im (inner marker), loc (localizer), mm (middle marker), ndb, obstacle, om (outer marker), runway, seaport, tacan, tower, town, village, vor.
  • id – airport ICAO code, required for q=airport.

Examples

Get a list of all airports:

    GET http://localhost:8080/navdb?q=airports

Get information about a specific airport:

    GET http://localhost:8080/navdb?q=airport&id=KSFO

Get VOR and NDB radio beacons at a specific location within 12 NM:

    GET http://localhost:8080/navdb?q=findWithinRange&lat=37.61&lon=-122.38&range=12&type=vor,ndb

GET /pkg

Aircraft installation package management. These queries don't contain parameters, only paths are used.

Examples

Get the aircraft directory installation path:

    GET http://localhost:8080/pkg/path

Get FlightGear version:

    GET http://localhost:8080/pkg/version

Refreshing the packages on the FlightGear side:

    GET http://localhost:8080/pkg/refresh

Get aircraft catalogs with all their packages:

    GET http://localhost:8080/pkg/catalogs

Get a specific aircraft catalog with all packages, where org.flightgear.fgaddon.stable_2024 is the catalog ID:

    GET http://localhost:8080/pkg/catalogById/org.flightgear.fgaddon.stable_2024

Get a specific aircraft package, where c182 is the aircraft identifier, in this case a Cessna 182:

    GET http://localhost:8080/pkg/packageById/c182

Sending a request to install an aircraft, in this case a Cessna 182:

    GET http://localhost:8080/pkg/install/c182
